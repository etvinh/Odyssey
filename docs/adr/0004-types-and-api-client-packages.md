# Domain types and generated client live in separate packages

`packages/api-client` holds Orval's output and nothing else, so it can be regenerated wholesale without anyone worrying about what else lived there. `packages/types` holds the drizzle-zod-derived domain types and enums — `orderStatus`, `orderChannel`, `OrderAction`, `dayOfWeek` — that both the Worker and the dashboard import, which is what keeps a status enum from being written down twice. The alternatives were skipping `packages/types` entirely and letting everything import from the generated client, or making it a thin re-export barrel; both leave the backend importing from a package named after the frontend's HTTP client, and neither gives the shared utilities in `packages/shared` anything to type against.
